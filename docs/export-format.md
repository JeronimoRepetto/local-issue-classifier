# Export format

The **Export…** dialog builds a report in one of three formats — **Text**, **Markdown** or
**HTML** (`options.format`, default `'text'`) — and saves it through the anchor-based download
helper (`src/adapters/download.ts`) as `{owner}-{repo}-issues-{YYYYMMDD-HHmm}.{ext}` (the stem
comes from `exportFilenameStem`; `ext` is `txt`/`md`/`html`).

All three formats are pure and deterministic: given the same analysis, options and clock, each
always produces the same bytes. The only line that varies run to run is `Generated`, since it
carries the injected clock.

## Output formats

All three renderers are built from one shared, pure `buildExportModel(analysis, options, now)`
(`src/domain/exportModel.ts`) — the same row partition (main/unclassified/dismissed, in the export's
final order) and the same header metadata (repository, generated, order, weights, scope, and a
`classifiedBy` summary), so the three formats can never show a different row set or a different
header from one another. Each format then renders that one model its own way:

| Format | Function | File | MIME | Use case |
|---|---|---|---|---|
| **Text** (default) | `formatExport(analysis, options, now)`, `src/domain/exportText.ts` | `.txt` | `text/plain` | Human-readable, fixed-width report; see "Format rules" below. |
| **Markdown** | `formatExportMarkdown(model)`, `src/domain/exportMarkdown.ts` | `.md` | `text/markdown` | GitHub-flavoured tables — meant to be pasted or dropped into an AI conversation. |
| **HTML** | `formatExportHtml(model, css)`, `src/domain/exportHtml.ts` | `.html` | `text/html` | A single self-contained file to open in a browser or share, with light/dark styling and no external requests. |

`formatExport` keeps its own `(analysis, options, now)` signature (its golden fixture, byte-for-byte
except `Generated`, is unchanged); `formatExportMarkdown`/`formatExportHtml` instead take the
already-built `ExportModel`, since `useExport()` builds one model and picks the renderer to hand it
to based on `options.format`.

### Classified by (comparing exports made by different models)

Every render — text's `Model` header line and Markdown/HTML's `Classified by` line — is derived
from the classification(s) actually behind the exported rows, so two exports of the same analysis
made by different models (e.g. a Jev run vs. a Kev run) can be told apart at a glance:

- **Nothing classified yet:** the line is omitted entirely (text) / not shown (Markdown, HTML).
- **One model behind every classified row:** the model id (and, for text only, its
  `questionsVersion`), e.g. `jev-1.13.0`.
- **More than one model:** `mixed: {model A}, {model B}, …`, in first-seen order, each model listed
  once.

### Markdown

`formatExportMarkdown(model)` builds an H1 title, a metadata bullet list — in order: Repository,
Generated, Classified by (when known), Order, Scope, Weights — then one GitHub-flavoured table per
non-empty section (`## Issues (N)`, and `## Unclassified (N)`/`## Dismissed (N)` when they have
rows). Every table shares the same columns: `#` (the issue number), `Title` (a link to the issue
when `includeUrls`), `Kind`, `Priority`, `Criticality`, `Complexity`, `Effort`, `Relevance`,
`Confidence` (only when `includeConfidence`; the classification's overall `minConfidence`, not a
per-dimension figure), `Status` (the row's classification status, plus the stored error message
when it errored) and `Updated`. An unclassified/dismissed-without-classification row shows `—` in
every classification-derived column. Titles and status error messages are third-party text: forced
onto one line and `|`-escaped so they can never split a table column.

Golden fixture (byte-for-byte, apart from `Generated`): `tests/fixtures/export/basic-report.md`.

### HTML

`formatExportHtml(model, css)` builds one self-contained document: `<!doctype html>`, a `<meta
charset="UTF-8">`, a `<title>`, a `<style>` block, a header with the same metadata list as
Markdown, one `<table>` per non-empty section (same columns as Markdown, plus optional per-row
bodies — see below), and a footer ("Generated by Issue Classifier"). No `<script>`, no
`<link>`, no `@import`, no font/CDN reference: the page opens and renders fully on its own.

- **Styling.** Domain code cannot import `src/ui/tokens.ts` (see `docs/architecture.md`'s
  dependency direction), so `useExport()` builds the `css` string itself — the light theme's custom
  properties at `:root` (`tokensToCss(tokens, 'light', ':root')`) plus a
  `@media (prefers-color-scheme: dark)` override with the dark theme's — and passes it to
  `formatExportHtml`. The system font stack is used directly (no `@font-face`, no web font).
- **Level chips.** Criticality/Complexity/Effort render as `<span class="chip chip--{level}">` with
  a small coloured `<span class="chip__dot">` plus the upper-cased level text — never an image or
  icon font — so meaning survives copy/paste and print.
- **Escaping.** Every value is HTML-escaped (`&`, `<`, `>`, `"`, `'`); titles, status error messages
  and issue bodies are third-party text and are never trusted as markup.
- **`includeBodies`** (`ExportOptions`, default `false`): when on, a row whose issue has a non-blank
  body gets an extra `<details><summary>Body</summary>…</details>` under its title, holding the
  trimmed body text. A row with no (or blank) body gets no `<details>`, even when the option is on.
  There is currently no dialog toggle for this option; it is set by seeding
  `working.exportOptions.includeBodies` directly (e.g. from `Preferences.defaultExportOptions`).
- **Hyperlinks vs. requests.** With `includeUrls` on, each title still links to the issue's own
  `htmlUrl` (`https://github.com/…`) — an ordinary hyperlink the reader can click, not a resource
  the page fetches automatically, so it does not count against "no external requests".

Golden fixture (byte-for-byte, apart from `Generated`): `tests/fixtures/export/basic-report.html`.
Its embedded token CSS is deterministic (a pure function of the fixed `tokens` object;
see `src/ui/tokens.ts`).

## Order modes (FB export: the export must match the table)

`options.orderMode` is `'table' | 'custom'`, defaulting to **`'table'`**. It decides which rows
appear and in what order — not just their sort:

- **`'table'` (default).** The export runs the *exact* table pipeline for the current analysis,
  via `domain/analysis.ts`'s `visibleRows(analysis, { filter: filterRows, sort: sortRowsBy })` —
  the same function `IssuesContainer.vue` calls to render the table. Concretely:
  - Dismissal is gated by `working.showDismissed`, not `options.includeDismissed`: a dismissed row
    appears (in its own Dismissed section, still) if and only if the table is currently showing
    dismissed rows, and it still has to pass the filter below to do so.
  - `filterRows(working.filter)` applies to every row alike — unclassified rows do **not** bypass
    it in this mode, unlike `'custom'` below. A narrowed filter (e.g. a criticality of "high") can
    hide an unclassified row from the export exactly as it hides it from the table.
  - The row order is `sortRowsBy(working.tableSort, working.priorityWeights)` — the table's own
    live multi-key sort, not `options.order`.
  - `options.scope`, `options.includeDismissed` and `options.includeUnclassified` are not consulted
    at all in this mode: reusing `visibleRows` directly is what keeps the export and the table from
    drifting apart again.
  - The header's `Order` line reads `Same as table: <rules>`, and `Scope` always describes the
    live filter (as if `scope: 'filtered'`), since the table always applies it.
- **`'custom'`.** The export's own independent order/scope/include settings apply, exactly as
  described in the rest of this document (own `options.order`, `options.scope`, dismissed rows
  gated by `includeDismissed`, unclassified rows bypassing the filter when `includeUnclassified` is
  on). The Order dialog row's segmented control switches modes; the sort-rule editor and "Use
  current table sort" are only shown in Custom.
- An analysis saved before `orderMode` existed has no such field; `domain/types.ts`'s
  `resolveExportOptions` (read at the `useExport()` boundary, same pattern as
  `resolveVisibleColumns`) tolerantly treats that as `'table'`.

`exportScopeCount`/`useExport().scopeCount` and the Export dialog's Download-disabled state always
count exactly the rows the current mode would write — in `'table'` mode that is
`visibleRows(...).length` for the current analysis.

## Format rules

The rules below describe the **Text** format specifically (`formatExport`). Markdown and HTML have
their own shapes — see "Output formats" above — but share the same row partition, ordering and
escaping-of-third-party-text principle.

- Fixed-width layout: every header label is padded to 11 characters before its colon; the row index
  is padded to at least 2 characters.
- Two-space indentation units: detail lines under a row are indented 4 spaces (two units).
- LF line endings only, UTF-8 without a BOM, exactly one trailing newline.
- Titles are forced onto one line: `\r\n`, `\r`, `\n` and `\t` all become a single space.
- Omitted optional parts leave no empty placeholder — no confidence, no `Include URLs` line, no
  empty section header for a section with nothing in it.
- Levels are upper-cased (`HIGH`/`MEDIUM`/`LOW`). Confidence is always 2 decimals.
- Dates are `YYYY-MM-DD`. The `Generated` line uses the local time zone (the injected clock's own
  `getHours`/`getMinutes`, no timezone conversion).
- The export never contains a secret: it is built only from `Issue`, `Classification` and the
  analysis's own working state — never from `Secrets`.
- Ties are broken by issue number ascending, same as the table (`sortRowsBy`'s final tie-break).

## Sections

1. **Header** — one label per line (see below).
2. **Main section** — a divider (`===...`, 72 `=` characters), then every issue that is classified
   and not dismissed, in the export order. In `'custom'` mode that order is `options.order`, applied
   to the rows `options.scope` selects; in `'table'` mode it is the table's own row set and order
   (see "Order modes" above).
3. **Unclassified (N)** — rendered whenever at least one row with no classification is included.
   In `'custom'` mode this is gated by `options.includeUnclassified`, and those rows bypass the
   working filter entirely: "Include unclassified" is a blanket toggle, not another filter
   dimension, so a narrowed filter (say, a relevance floor no unclassified row can satisfy) never
   empties this section. In `'table'` mode unclassified rows follow the table exactly instead: they
   go through the same filter as every other row, with no bypass.
4. **Dismissed (N)** — rendered whenever at least one dismissed row is included. In `'custom'` mode
   this is gated by `options.includeDismissed`; in `'table'` mode it follows `working.showDismissed`
   instead (and the row still has to pass the filter). Dismissed rows never appear anywhere else,
   classified or not.

Sections are separated by a blank line; entries within the main section are separated by a blank
line too.

## Header lines

| Label | Content |
|---|---|
| `Repository` | `{owner}/{repo} ({stateFilter} issues)`, plus ` — "{name}"` when the analysis was renamed away from its default name. |
| `Generated` | `YYYY-MM-DD HH:mm (local time)`, from the injected clock. |
| `Model` | `{model} · questions v{questionsVersion}` from the first classified row found; omitted when nothing is classified yet. |
| `Order` | `'custom'` mode: the export order, e.g. `Priority (high→low), Effort (low→high)`. `'table'` mode (default): `Same as table: <rules>`, i.e. `working.tableSort` formatted the same way. Date keys read `newest→oldest` / `oldest→newest` instead. |
| `Weights` | `Criticality N · Relevance N · Complexity N (inverted) · Effort N (inverted)`, the analysis's `priorityWeights`, always shown even if every weight is 0. |
| `Scope` | `{filtered view|all issues} — {main count} of {total issues}`, plus ` (filters: …)` for an active, non-default filter. `'custom'` mode reads this from `scope`; `'table'` mode always behaves like `'filtered'`, since the table always applies `working.filter`. |
| `Note` | A fixed sentence about the ordinal, model-based nature of levels/relevance/priority. |

## Main-section entry

```text
 1. #812  Crash when rendering empty list
    Priority   : 83/100
    Criticality: HIGH (conf 0.91) · Complexity: MEDIUM (conf 0.74) · Effort: LOW (conf 0.82)
    Relevance  : 88/100 (0.77) · Kind: bug · Labels: bug, regression
    Opened 2026-09-02 by @jdoe · updated 2026-09-20 · 3 comments
    https://github.com/acme/widgets/issues/812
```

- `Priority` shows `—` when every priority weight is 0 (`priorityOf`/its export-side equivalent
  returns `null`; see the note on Task 14 below).
- Confidence parentheticals (`(conf 0.91)` for a level, `(0.77)` for relevance) are omitted
  entirely when `includeConfidence` is false, or when that particular dimension's confidence is
  absent (the Jev response did not include one) — never rendered as an empty placeholder.
- `Labels` shows `—` when the issue has none.
- The URL line is omitted entirely when `includeUrls` is false.
- `comment`/`comments` is pluralized on the comment count.

## Compact entry (Unclassified / Dismissed)

```text
 -  #815  Add Svelte adapter (not classified: Rate limited — retried 3×)
```

The `(not classified: …)` suffix only appears for a row with `status: 'error'` and a stored error
message; otherwise it is omitted.

## Edge cases

- **Nothing in scope.** When no row would appear in any section, Download is disabled and the
  dialog shows "Nothing to export." (`exportScopeCount`, used by `useExport().scopeCount`).
- **Empty main section, non-empty other sections.** The main section's divider still appears with
  no entries under it; the Unclassified and/or Dismissed sections still render if they have rows.

## API surface

| Export | From | Purpose |
|---|---|---|
| `buildExportModel(analysis, options, now)` | `src/domain/exportModel.ts` | The shared row partition + header metadata (title, repository, generated, modelLine, classifiedBy, order, weights, scope, note, main/unclassified/dismissed) consumed by all three renderers. Pure. |
| `exportScopeCount(analysis, options)` | `src/domain/exportModel.ts` (re-exported from `exportText.ts`) | Total rows that would appear in any section — backs the "Nothing to export" gate. |
| `formatExport(analysis, options, now)` | `src/domain/exportText.ts` | Builds the full Text report. Pure. |
| `formatExportMarkdown(model)` | `src/domain/exportMarkdown.ts` | Builds the full Markdown report from an already-built `ExportModel`. Pure. |
| `formatExportHtml(model, css)` | `src/domain/exportHtml.ts` | Builds the full self-contained HTML report from an `ExportModel` and a caller-supplied token CSS string. Pure. |
| `exportFilenameStem(analysis, now)` | `src/domain/exportText.ts` | `{owner}-{repo}-issues-{YYYYMMDD-HHmm}`, without the format extension. |
| `sortRowsBy(rows, rules, weights?)` | `src/domain/sort.ts` | The stable multi-key sort used for the main section, and by the table itself. |
| `visibleRows(analysis, options?)` | `src/domain/analysis.ts` | Dismissal → filter → sort, in that order; `orderMode: 'table'` calls this the same way `IssuesContainer.vue` does. |
| `resolveExportOptions(stored)` | `src/domain/types.ts` | Tolerant read of `exportOptions`; fills in `orderMode: 'table'`, `format: 'text'` and `includeBodies: false` for an analysis saved before those fields existed. |
| `downloadText(text, filename, mime?)` | `src/adapters/download.ts` | Anchor-based download: Blob URL → `<a download>` click → revoke on the next tick. `mime` defaults to `text/plain;charset=utf-8`; `useExport().download()` passes the format's own MIME for Markdown/HTML. |
| `useExport()` | `src/composables/useExport.ts` | `options` (incl. `format`), `setOptions`, `setOrder`, `useCurrentTableSort`, `previewText`, `scopeCount`, `download` — `previewText`/`download` switch renderer, extension and MIME on `options.value.format`. |

## Priority (Task 14)

`exportText.ts` imports `priorityOf` from `domain/priority.ts` directly; the golden
fixture stayed byte-identical after the swap, since the formula was already the exact one used
here. The table's own `priority` sort key (`sort.ts`) uses the same `priorityOf`, so the export
order and the table order agree: `null` (unclassified, or every weight 0) always sorts last in
both directions, with the final tie-break by issue number.
